# 双城沙盘验收记录

日期：2026-09-09。

## 场景与构建

- 两城各 8 个唯一地标，坐标、相机位置与观察目标均为有效有限值。
- 几何属性、世界矩阵、实例矩阵通过检查。
- 在 0、0.016、1、10、60、600、3600 秒采样，动画更新未出现数值异常。
- 成都 12 个、重庆 10 个动态对象均发生位移。
- 成都 158 个 mesh，8570 个实例；重庆 206 个 mesh，3646 个实例。
- 两城模型完整 x/z 范围均为 ±105，底面 y=-4.8。
- 生产构建通过。主包包括 Three.js，约 660 KB，gzip 约 176 KB；Vite 的大于 500 KB 提示为体积提示，不影响构建。

## 浏览器验收

- Chrome 桌面预览：两城均成功渲染，城市切换、全景与近景、地标信息联动正常。
- 成都检查了全景、IFS 与太古里近景，确认熊猫和街区可辨认。
- 重庆检查了全景、洪崖洞近景与夜景，确认桥梁、两江、来福士与台地呈现。
- 390 × 844 手机视口检查：城市切换、地标下拉入口、IFS 近景及底部按钮均可用，IFS 熊猫完整入镜。
- 导览从来福士自动推进至李子坝等后续地标，卡片与选中状态同步。
- 发现并修正首次 requestAnimationFrame 时间可能早于初始化时刻的问题，将单帧时间限制在 0～0.06 秒。
- 按 Three.js 当前版本改用 PCFShadowMap。
- 修正夜景文字颜色继承、近景侧栏可读性与手机底栏遮挡导览按钮的问题。

## 交付范围

本地静态网页与完整源码。所有模型均为程序化几何，运行无需地图账号、外部图片或 API 密钥。距离、道路和地形经过艺术化压缩，没有逐栋测绘和导航精度的承诺。未执行公网部署。

## 成都南向扩展：2026-09-09

本节追加本次扩展证据；上方每城 8 个地标、固定底座范围和浏览器验收均属于扩展前版本，不作为本次扩展的验收结论。

验证脚本现按每城必须存在的地标 ID 检查集合：成都保留原 8 个，并要求文殊院、人民公园、金融城双子塔、西博城和兴隆湖；重庆保留原 8 个。检查地标 ID 唯一性、片区、统计数量与实际数量一致，底座 x/z 范围接近各城声明的 `bounds`，以及地标位置、观察目标和相机有效性。几何、世界矩阵、实例矩阵与七个时间样本的动画检查继续保留。

片区检查依据 `city.regions.id` 与地标 `zone` 的引用关系，包含片区 ID 唯一性、名称、相机位置和观察目标有效性，不绑定具体展示文案。所有标记为动态的对象均须在采样中发生位移。

扩展场景完成后实际执行 `npm run verify`，退出码为 0，结果如下：

| 检查项 | 成都 | 重庆 |
| --- | --- | --- |
| 地标集合 | 原 8 个保留，新增 5 个，共 13 个 | 原 8 个保持不变 |
| Mesh / 实例 | 248 / 11098 | 206 / 3646 |
| 动态对象 / 实际发生位移 | 12 / 12 | 10 / 10 |
| 底座 x 范围 | -105～105 | -105～105 |
| 底座 z 范围 | -105～205 | -105～105 |
| 整体几何 y 范围 | -4.8～44.3 | -4.8～44.759 |

两城几何属性、世界矩阵和实例矩阵均为有限值；在 0、0.016、1、10、60、600、3600 秒七个时间样本更新通过。地标数量统计与实际数组一致，地标位置和观察目标位于各自边界附近，底座范围匹配声明的 `bounds`。重庆整体几何 x 最小值为 -105.999，略超出底座边沿；本检查区分完整几何范围与底座尺寸，不将二者混为一项。

脚本只验证整体可视几何边界和相机数据，合并材质模型无法可靠关联到单个地标，因此不能据此声称每个新增建筑已具备视觉辨识度。
